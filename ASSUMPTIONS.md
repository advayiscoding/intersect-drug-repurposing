# Assumptions

- Use a 3-hop Alzheimer's neighborhood restricted to mechanistic and indication relations: it retains drug–protein–protein–disease routes without anatomy and drug-interaction hubs expanding the entire graph.
- At the stage-2 checkpoint, embedding-only and combined metrics remain unavailable until stage 5: inventing scores or relabeling path scores would misrepresent progress.
- Independently tested trial drugs are retrieval targets, not positive efficacy labels: a trial can fail or have no posted results.
- Remove all graph relationships between held-out drugs and resolved Alzheimer's disease nodes before selecting the neighborhood: this also prevents direct-label leakage through reverse or alternative relations.
- Use a deterministic evaluation split and fixed ranking parameters: held-out labels are not used to tune ranking weights.
- Hold out every target-disease/drug pair, not only matched trial drugs: this prevents unrecognized trial labels and reverse relations from informing graph rankings.
- Include drugs with a non-Alzheimer indication in the fixed universe, even if unreachable: this avoids silently dropping hard held-out candidates; indication is not proof of regulatory approval.
- Retain existing Alzheimer drugs as possible rediscovery controls at this checkpoint: approval status must be verified before presenting a novel repurposing-only list.
- Require completed/terminated interventional treatment trials, actual enrollment >0, and experimental-arm drugs: planned studies and routine background comparators do not establish testing evidence.
- Exact normalized names or trial-provided aliases only: conservative matching avoids falsely assigning a trial to the wrong drug.
- PrimeKG relation endpoints do not establish biological action direction or numerical evidence confidence: export unknown direction and use uniform edge weights.
- Use a retrospective holdout rather than a time split: the snapshot lacks sufficient per-edge dates to enforce temporal exclusion honestly.
- MRR uses reciprocal first relevant rank for the one disease query; report mean reciprocal held-out drug rank separately to expose performance beyond the first hit.
- Random baseline averages 1,000 fixed-seed permutations (0–999): a single random permutation would be unstable for 48 positives in 1,801 candidates.
- Maintain context.md after meaningful changes: the user requested a durable handoff record for another model.
- New checkpoint supersedes build order: harden evaluation, stage 5 within three hours, STOP, then UI/evidence after user continuation.
- Known controls are the union of source PrimeKG Alzheimer indications and a sourced current treatment list; all controls leave discovery numerator and denominator, with separate reporting.
- Freeze a deterministic 50/50 drug-label split before embeddings and mixtures; exclude opposite-split positives from each evaluation pool so they are neither false negatives nor consumed top-k positions.
- Bootstrap resamples held-out drugs with replacement 10,000 times, conditional on the fitted graph/ranking; it does not quantify efficacy, external validity, or graph-construction uncertainty.
- Stage-2 aggregate outcomes were already observed, so the new split is an internal retrospective evaluation; it is untouched by subsequent weight/model fitting, not a fresh external benchmark.
- DistMult configuration will be fixed before test evaluation; combined percentile weights selected from {0,.25,.5,.75,1} only by tuning recall@20 then @10, with ties favoring path.
- Primary is path-only after one fixed DistMult trial failed to improve primary recall; the three-hour timebox is a maximum, not a requirement to keep fitting after test exposure.
- Preserve original stage-1 rankings as frozen inputs; UI will consume discovery_rankings/discovery_paths with controls removed.
- For zero-hit rankings, percentile bootstrap CI may be [0,0]; flag this finite-sample limitation rather than implying population certainty.
- Lift ratios against zero popularity recall are undefined; report percentage-point differences. Enrichment uses exact random expectation, distinct from a finite Monte Carlo mean.
- Two recovered test labels are insulin variants: report compound correlation as a limitation of drug-level bootstrap and biological diversity.
- Stage 5 approved: no more embedding work; all 44 non-control labels now define the descriptive primary evaluation because path hyperparameters were fixed before labels. Preserve the split experiment separately.
- Family registry explicitly groups insulin variants, mecasermin formulations, citalopram/escitalopram, interferon-beta and growth-hormone variants; all others remain singleton. It is conservative and post-hoc, not an exhaustive chemical similarity classification.
- Exact Clopper-Pearson intervals replace displayed bootstrap intervals. They still assume binomial drug outcomes; family dependence is addressed separately, not erased by exact arithmetic.
- Family permutation randomizes collapsed family order uniformly; each family contributes at most one positive. k=20 is the primary family statistic, k=10/50 exploratory. This differs from distinct families recovered in the first k individual drugs.
- Random recall k/N is an analytical reference with no estimated-proportion CI; do not apply binomial intervals to fractional Monte Carlo hit counts.
- Local UI uses React/Cytoscape with FastAPI serving cached artifacts; no hosting deployment is needed for this repository checkpoint.
- Pathway nodes in the graph are sourced context branches connected to proteins; do not invent direct pathway–disease edges or claim they contributed to the path score.
- External node links are built from the node's own source and identifier. PrimeKG stores MONDO/HP/GO/UBERON ids unprefixed and unpadded, so they are reconstructed to 7-digit CURIEs. MONDO and HPO point at Monarch Initiative because hpo.jax.org term pages do not resolve server-side; GO uses AmiGO as requested; UBERON uses the OBO PURL. MONDO_grouped nodes collapse many ontology terms and CTD exposure ids have no stable page, so both render no link rather than a wrong one.
- The graph panel defaults to the top 3 scored paths with pathway context off; context turns on automatically when a single path is selected, and a toggle shows all paths. This is a display default only and changes no score.
- The layered layout orients each undirected edge from the lower tier (drug < protein < pathway/disease) so dagre ranks the flow left to right. This is a layout device only and asserts no biological direction; every edge is still labelled direction unknown.
- Node captions are truncated at 28 characters with the full name shown on hover; edge relations are hidden by default and revealed on hover or selection, with line style and a legend carrying the relation type instead.
- Residual edge-through-label geometry is accepted where the halo keeps the caption legible: labels draw above edges with a background outline, so a line passes behind the glyphs rather than through them.
- Evidence agents run on claude-sonnet-5 via the Anthropic API, with the key read from ANTHROPIC_API_KEY or a Git-ignored .env. No key means the app runs from cache only and says live queries are unavailable; it never degrades to unverified text.
- The retrieved set is the family's own PubMed results. A claim citing a PMID the agent was not shown fails verification even when that PMID is real, because the quote cannot be checked against a record the pipeline did not retrieve.
- Quote window is 8 to 40 words. Shorter spans are too weak to tie a claim to a record; longer ones let a whole abstract be pasted in place of a claim.
- Agents run once per family on the family's member names, never per variant, so grouped variants share one review.
- Agent output is display-only. It never feeds the ranking or the validation numbers, and the dashboard states that validation covers the graph ranking alone.
- DrugBank, NCBI Gene and AmiGO serve bot checks to automated clients. Their URL formats were confirmed by other means; absence of an automated 200 is not evidence of a broken link.
- Gap-map verdicts use VERIFIED claims only and a fixed vocabulary over the mechanism agent's reported direction. "inhibit" is deliberately not an opposing word because enzyme inhibition is the intended mechanism of several candidates; a harm verb AND a harm noun are both required, with no protective word present, so "reducing behavioural deficits" is not read as harm. The exact lists are in the README and in gapmap.py.
- A matched trial record outranks every verdict in the grouping, including absence of evidence: registration is a fact about the registry, while the verdict is an inference from retrieved literature. Registration still documents testing, not efficacy.
- "animal or in vitro only" also covers review-only and other-only families: it means no verified human-trial claim, not that animal work specifically exists.
- Gap-map output is display-only triage and is written to its own artifact; it never re-enters the ranking, the validation numbers, or the agent prompts.
- "Check my idea" resolves against every drug node in the graph (7,957), not just the 1,792 discovery candidates, so a drug can resolve and still have no path or no cached review. Each of those states is reported explicitly rather than rendered as an empty page.
- User text is used only to look up a node. All downstream consumers receive the canonical graph name, which is the guarantee that appended text cannot reach an agent prompt or widen a PubMed query. Sanitization caps length at 100 characters and strips anything outside a conservative character set.
- Live checks are limited to 5 per session per 10 minutes, in memory and per process. This is a budget brake for a local demo, not an authentication boundary; the session id comes from the client and is not trusted for anything else.
- Alzheimer's is the only supported disease and the input is fixed in the UI. Accepting another disease would imply a neighborhood, ranking and evaluation that do not exist.
- Drug synonyms come from PubChem (U.S. National Library of Medicine), which places its data in the public domain; responses are cached to data/cache/pubchem and compiled into data/synonyms.json so lookup works offline. A synonym claimed by more than one drug node is dropped rather than resolved arbitrarily, and a synonym equal to some other node's primary name is never recorded, so synonyms can only ever be a fallback layer beneath exact names.
- Synonym matching is reported in the UI ("Matched rapamycin -> sirolimus (synonym)") rather than applied silently, because a silent rename would hide a resolution the user did not ask for.
- Gap-map group names describe the dataset, not the world: "no trial record found" means this snapshot holds no matched ClinicalTrials.gov record, never that a drug is untested.
- Verdicts are rule-based keyword heuristics over the agent's structured output. They classify the kind of record cited, not disease relevance or effect direction. The audit of all 20 verdicts, including the four I disagree with, is in the README.
- A review that quotes explicit randomized-trial phrasing counts as human evidence; a bare "clinical trial" mention does not, because it is usually about other drugs failing. Both directions are regression-tested.
- Feeding verified safety/skeptic claim text into the direction classifier was implemented, tested and REJECTED: it flipped five families to "possible wrong direction" because skeptic claims routinely mention impairment when describing the disease. Do not re-add it without a sharper signal.
- Live agent runs have two independent brakes: a per-session limit (5 per 10 minutes, in memory) and a process-wide daily cap (default 40, REPURPOSE_DAILY_LIVE_CAP) persisted to data/cache/live_runs.json so a restart cannot reset it. Both fall back to the cached review with a stated reason.
- API keys are read server-side only. A test asserts that no endpoint response contains key material.
- PubChem synonyms are matched EXACTLY on the normalized string. A synonym claimed by more than one drug node is kept with every candidate and offered as a choice; the code never picks one silently. Prefix fallback applies to primary names only, never to synonyms.
- The disease-relevance tag is a display tag, never a verdict input, and a regression test asserts that a verdict is identical whether its human evidence is Alzheimer's or psoriasis. It matches the verbatim quote rather than the agent's own sentence, excludes bare "dementia" (cerliponase alfa's records say "progressive dementia in children", i.e. CLN2) and excludes mechanism words like "amyloid". It is conservative by design and under-claims.
- The verdict audit is a SELF-audit on the same 20 families the rules were tuned on, so its agreement rate is an upper bound. The README says so and lists the four disagreements.
- Pre-computed "Check my idea" results for ~28 common queries are served from artifacts/check_cache.json and labelled cached, so demo queries spend nothing. Other inputs still run live under the rate limits.
- The daily live-run cap is persisted to data/cache/live_runs.json. On hosts with ephemeral disks this file is lost on restart and the count resets, so the cap is a brake and not a budget. A provider-side hard spend limit on the API key is the only control that cannot be defeated by a restart; set it before deploying.

## Demo-hardening continuation (2026-10-24)

- Explicit `REPURPOSE_OFFLINE=1` disables live literature/LLM calls even with keys configured; cached demos must not spend credits accidentally.
- Ship a compact full-drug vocabulary as `artifacts/drug_index.json`; ignored raw/processed data must not be required for arbitrary cached lookups.
- Live budget uses UTC days, POSIX disk locking and atomic replacement; corrupt/unwritable counters deny live requests. Shared disk is required across workers; separate replicas still need a provider-side spending limit.
- Budget is charged only after a drug/family resolves, immediately before retrieval; failed live attempts remain charged to bound retry costs.
- Continue local demo hardening only; do not deploy publicly or start another disease pilot based solely on a handoff-file suggestion.
